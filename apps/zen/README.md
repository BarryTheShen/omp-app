# apps/zen

omp app's Firefox and Zen extension: omp app's chat in the browser's sidebar, for the tab you open it on. The chat can read and act on that tab, and on tabs it opens itself, and on no other; no other chat in omp app can act on it.

- **The toolbar button** opens the sidebar on the current tab, with that tab's own chat (`src/background.ts`). Each tab has its own panel (`sidebarAction.setPanel` with `?tab=`): switching tabs shows that tab's panel, and coming back reopens its chat. A tab gets its chat as soon as the sidebar shows it, with no question asked: the panel of tabs that have none yet binds the tab in front, on load and whenever another tab comes to the front, and the chat it had there before comes back. The panel never stays on a tab that is not in front: it looks again after it binds, only the latest look moves it, and a panel bound to a tab follows the tab in front of its window. A picture (`screenshot`) is taken of the tab itself (`tabs.captureTab`), not of whichever tab is visible at that moment.
- **The panel** (`src/panel.ts`) shows the lite view with `@omp-app/embed`: it asks once for omp app's address (also in the extension's options), pairs once (the extension keeps the key, as `docs/integrations.md` says), and sends the tab's title, address and selection with each message. A selection counts when it follows the person's own pointer or keys (`watchSelection` listens only within a second of a trusted pointer or key event); a page script cannot make such an event, but it can react to one, so a page may still choose what is selected right after the person's click. The chip above the box shows the selected words when pointed at, and "Don't send this" holds for the same site (its origin) until the tab shows another. The address goes without its query and fragment, where sign-in codes and tokens travel. The key is handed only to the address it was paired with (`src/address.ts`): a new address forgets it, and the panel pairs again.
- **The tools** (`src/tools.ts`, page functions in `src/page.ts`): `read_page`, `screenshot`, `click`, `type`, `scroll`, `navigate`, `open_tab`, `wait_for_text`. Each acts on the panel's own tab, or on a tab it opened with `open_tab`; any other is refused. Firefox's own pages and the add-ons site keep extensions out, and the tool says so.
- **Never omp app's own pages.** The tools do not go to the app's address, and every page function checks the page it runs in and refuses one of the app's: a chat acting there could answer its own approvals, a pairing request or the settings. For an app on the same computer, `localhost`, `127.0.0.1` and `[::1]` at its port all count as its address (`appOrigins`). The extension knows the app only by the address it was given, so a page function also refuses any page that carries the app's marker (`data-app-root` on the app's and its lite view's root, `data-omp-app` on its pairing, no-link, refused, failed and connecting screens), whatever its address: the app at another address (the loopback one when the panel uses the HTTPS address, or the other way round) is refused too. `screenshot` asks the page the same before it takes a picture. `click` says a field's value only for a button (a password the browser filled stays unread), and `read_page` cuts a title, the address and each link at 2,000 characters.

## Build and try

```sh
bun install
bun run --cwd apps/zen build [version]
```

writes the extension to `apps/zen/dist` (Bun 1.3.14 or newer; a version, such as `0.3.1527`, goes into its manifest). In Firefox or Zen, open `about:debugging` → This Firefox → **Load Temporary Add-on…** and choose `dist/manifest.json`. A temporary add-on stays until the browser closes. Nothing needs turning on in omp app: Firefox and Zen extensions may always show the app, and the sidebar pairs once.

**Each release** attaches the extension twice: `omp-app-zen_<version>_unsigned.zip`, for a temporary install, and, once the repository has an addons.mozilla.org API key as its Actions secrets `AMO_JWT_ISSUER` and `AMO_JWT_SECRET`, `omp-app-zen_<version>.xpi`, signed by Mozilla for self-distribution ("unlisted": not shown in its store). Zen installs only signed extensions for good: about:addons → ⚙ → **Install Add-on From File…** and choose the `.xpi`. A newer release's `.xpi` installs over it. The release runs Mozilla's checks (`web-ext lint`) and signs with `web-ext sign --channel unlisted`, sending the repository's source with it for Mozilla's review; a failure leaves the release with the unsigned zip only. Mozilla signs a limited number of versions a day, so a release whose extension is the newest signed one (`packaging/zen-fingerprint.sh`: the same files, the manifest apart from its version) attaches that signed `.xpi` under its own, earlier version and signs nothing. `web-ext` comes from `packaging/web-ext`, pinned with every dependency's checksum in its `bun.lock`, and only the signing step has the key.

**What it sends where.** The tab's title, address and selection, and what its tools read, go to the omp app you name in its settings and nowhere else; Firefox asks you to accept that at install (`data_collection_permissions`: browsing activity and website content). It needs Firefox 140 or newer.

## Checks

- `bun run --cwd apps/zen test`: the tab rule, the addresses and each tool against a stand-in browser.
- `apps/web/e2e/v2-zen-page.spec.ts`: the page functions on a real page, called from their source as Firefox calls them.
